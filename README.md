# JEWAR · حاسبة رسوم ترخيص الأبنية

تطبيق أندرويد (Capacitor) لحساب رسوم الترخيص وغرامات التجاوزات وحصص المكتب والنقابة، مع سجل للزبائن.
معرّف التطبيق: `com.jewar.app` · الاسم على الهاتف: **JEWAR**

## هيكل المشروع
| المسار | الوظيفة |
|---|---|
| `www/calc.js` | معادلات الحساب (مطابقة لملف الإكسيل) |
| `www/app.js`, `style.css`, `index.html` | الواجهة |
| `tests/calc.test.js` | اختبار يقارن النتائج بخلايا الإكسيل الأصلية (`npm test`) |
| `android/` | مشروع أندرويد (مُولَّد، يُرفع كما هو) |
| `.github/workflows/build-apk.yml` | بناء الـ APK تلقائيًا |

## الإعداد لمرة واحدة: مفتاح التوقيع
حتى يتحدث التطبيق **فوق النسخة المثبّتة وتبقى بياناتك**، يجب أن يُوقَّع كل إصدار بنفس المفتاح.
1. في المستودع: **Settings ← Secrets and variables ← Actions ← New repository secret**
2. أضف سرّين:
   - `JEWAR_KEYSTORE_BASE64` ← محتوى ملف `jewar.keystore.base64.txt` كاملًا
   - `JEWAR_KEYSTORE_PASSWORD` ← كلمة المرور المرسلة لك
3. احتفظ بنسخة من `jewar.keystore` وكلمة المرور في مكان آمن خارج GitHub (مدير كلمات مرور أو USB). **إن ضاعا لا يمكن تحديث التطبيق فوق نسخته المثبّتة.**
4. لا ترفع ملف المفتاح إلى المستودع أبدًا (`.gitignore` يمنع ذلك).

## بناء الـ APK
- كل دفعة (push) إلى `main` تبني APK وتنشره في **Releases** باسم `JEWAR.apk`.
- أو يدويًا: **Actions ← Build JEWAR APK ← Run workflow**.
- حمّل `JEWAR.apk` من صفحة Releases على الهاتف وثبّته (يطلب أندرويد السماح بالتثبيت من المتصفح أول مرة).
- يزداد `versionCode` تلقائيًا مع كل بناء، فيُقبل كل إصدار كتحديث.

## الحفاظ على البيانات
- تُخزَّن البيانات داخل التطبيق (localStorage + Preferences) وتبقى عند التحديث فوق النسخة القديمة.
- **لا تحذف التطبيق قبل التحديث**، فالحذف يمسح بياناته.
- من شاشة «السجل»: «حفظ نسخة احتياطية» و«استعادة نسخة»، و«تصدير السجل (Excel)».

## تعديل المعادلات أو القيم الافتراضية
- القيم الافتراضية والمعادلات في `www/calc.js`، ثم شغّل `npm test` للتأكد من مطابقتها لملف الإكسيل.
- القيم المرجعية تُعدَّل أيضًا من داخل التطبيق (شاشة «القيم المرجعية») دون بناء جديد.

## تشغيل محلي للتجربة
افتح `www/index.html` في المتصفح.
